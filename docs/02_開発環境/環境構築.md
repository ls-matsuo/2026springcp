# 環境構築

開発環境は Docker Compose で起動します。

## 起動方法

プロジェクトルートで実行:

```bash
docker compose up -d
```

初回または `containers/web/Dockerfile` 変更後はビルドを実行:

```bash
docker compose up -d --build
```

## 停止方法

プロジェクトルートで実行:

```bash
docker compose down
```

コンテナとネットワークが削除されます。ボリュームマウントしている DB ファイル等は残ります。

## コンテナ構成

| ディレクトリ | 役割 |
|-------------|------|
| `containers/web/` | PHP + Apache（Dockerfile 等） |
| `containers/database/` | DB まわり（本プロジェクトは SQLite・コンテナなし） |

## データベース（SQLite）

**専用コンテナはありません**。ファイルベースの SQLite を PHP 内蔵（pdo_sqlite）で利用します。

- **DB ファイル**: `entry/includes/db/2026springcp.db`（初回適用時に自動作成。`db/` のみ www-data に chown し、includes 本体のオーナーは変えない）
- **アクセス**: PHP の PDO からアプリ内でのみ参照
- **永続化**: プロジェクトをボリュームマウントしているため、コンテナを消してもファイルは残る

### スキーマの適用

**web コンテナ起動時に自動で実行**されます（entrypoint で `init_db.php` を実行）。`CREATE TABLE IF NOT EXISTS` のため、初回のみテーブルが作成され、2 回目以降はスキップされます。

手動で実行する場合:

```bash
docker compose exec web php /var/www/html/2026springcp/containers/database/init_db.php
```

※ 納品時はスキーマ適用済みの .db を Zip に同梱するため、受け側でスキーマ適用は不要。`init_db.php` は `containers/database/` にあり納品物（entry 等）には含めない。

### .db のバックアップ・復元

SQLite の .db は単一ファイルなので、コピーでバックアップ・復元できます。

**バックアップ（現状を退避）**
```bash
cp entry/includes/db/2026springcp.db entry/includes/db/2026springcp.db.bak
```

**復元（.bak を本番の .db に戻す）**
```bash
cp entry/includes/db/2026springcp.db.bak entry/includes/db/2026springcp.db
```

※ `.db.bak` は `.gitignore` に含まれており、リポジトリにはコミットされません。

## メール設定（.env）

SMTP のホスト・ポート・認証等は **entry/includes/.env** で行う。includes 配下のため .htaccess で保護され、Web から直接参照されない。`entry/includes/.env.example` をコピーして `.env` を作成し、利用する SMTP サーバに合わせて `MAIL_*` を設定する。

```bash
cp entry/includes/.env.example entry/includes/.env
# entry/includes/.env を編集して MAIL_HOST, MAIL_PORT, MAIL_USER 等を設定
```

※ `.env` は `.gitignore` で除外されている。開発で Mailpit 等を使う場合は、.env にそのホスト・ポートを書けばよい。
